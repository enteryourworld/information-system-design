# Коротко к защите

а. **Делегация** — поручение работы другому объекту. Здесь YAML-репозиторий использует файловую логику JSON-репозитория, а адаптер — SQL-класс. Наследование означает «является», делегация — «использует».

б. **Ассоциация** — связь объектов через ссылки. Агрегация: части существуют независимо от целого; композиция: жизненный цикл части связан с целым. Ромб ставится у целого.

в. **Стратегия** позволяет подставлять алгоритм с общим контрактом, например способ сортировки. Алгоритм выбирается отдельно от использующего его объекта.

г. Пример наследования: `Dog extends Animal`. Пример делегации алгоритма: объект хранит `Comparator` и передаёт ему сравнение. В первом случае меняется реализация в подклассе, во втором — объект-помощник.

д. Если нужен один простой алгоритм без вариантов, достаточно обычного метода; вводить паттерны заранее не требуется.

е. **ClientRepDb** содержит SQL, а отдельный **Database** открывает JDBC-соединения. Репозиторий делегирует ему подключение и закрывает соединение через try-with-resources. **ClientDbAdapter** переводит общий контракт репозитория в его методы. ORM не используется.

ж. JDBC возвращает SELECT как **ResultSet**. SQL-класс преобразует строки в `Client`, `Optional<Client>`, список `ClientShort` или число для COUNT и закрывает ресурсы.

з. **Singleton** обеспечивает один экземпляр сервиса. Здесь это `Database`: закрытый конструктор, статическое поле INSTANCE и метод getInstance(). Отдельные запросы используют отдельные соединения.

и. Проверка Singleton: два вызова `Database.getInstance()` должны быть равны по `==`. Статическая инициализация поля выполняется JVM один раз.

й. Поля хранят состояние, методы определяют действия и проверки. Статические методы нужны без готового экземпляра: пример — `Database.getInstance()`; другой пример — проверка формата телефона до создания клиента.

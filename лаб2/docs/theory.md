# Ответы к защите ЛР2

## а. Делегация вместо наследования

Наследование выражает отношение «является». Делегация — «использует помощника». Если нужно менять способ хранения, достаточно передать другой объект, а не создавать цепочку наследников с чужими обязанностями.

```java
interface Engine { void start(); }
final class Car {
    private final Engine engine;
    Car(Engine engine) { this.engine = engine; }
    void start() { engine.start(); }
}
```

Машина не является двигателем, поэтому `Car extends Engine` неверно. В работе `ClientRepJson` и `ClientRepYaml` делегируют операции `FileClientRepository`, а `ClientRepDb` — сервису `Database`.

## б. Ассоциация

Ассоциация — связь объектов: один объект знает о другом и может обращаться к нему. Однонаправленная ассоциация показывает доступ в одну сторону; двунаправленная — в обе. Кратность описывает число связанных объектов: `1`, `0..1`, `0..*`, `1..*`.

- Обычная ассоциация: адаптер хранит ссылку на SQL-репозиторий.
- Агрегация, пустой ромб у целого: команда включает сотрудников, которые существуют независимо от команды.
- Композиция, закрашенный ромб у целого: часть принадлежит одному целому, которое управляет её жизненным циклом, например строки конкретного заказа.

Пунктирная стрелка обозначает зависимость, например использование типа в параметре метода. Пустой треугольник со сплошной линией — обобщение; с пунктирной — реализация интерфейса. Ромб не ставится автоматически из-за наличия поля или списка.

## в. Стратегия

Strategy позволяет выбирать алгоритм во время выполнения. Клиент делегирует алгоритм объекту с общим контрактом. В работе `ClientQuery` выбирает `Comparator<Client>` через `ClientSort`, а файловая логика получает кодек JSON или YAML.

## г. Наследование и стратегия

```java
class Animal { void speak() { System.out.println("Звук"); } }
class Dog extends Animal {
    @Override void speak() { System.out.println("Гав"); }
}
```

Собака является животным; реализация определяется классом объекта.

```java
interface SortStrategy { void sort(java.util.List<String> values); }
final class Names {
    private final SortStrategy strategy;
    Names(SortStrategy strategy) { this.strategy = strategy; }
    void sort(java.util.List<String> values) { strategy.sort(values); }
}
```

В `Names` алгоритм передаётся отдельно. `Names` не является сортировкой. В ЛР2 конкретные классы репозиториев не наследуются друг от друга; общий контракт задают интерфейсы.

## д. Когда паттерн не нужен

Если требуется один фиксированный способ обработки нескольких строк, простого метода достаточно. Добавление фабрик, декораторов и стратегий без вариантов поведения усложнит код. В этой работе паттерны нужны из-за трёх хранилищ и требований задания.

## е. Какой класс работает с БД

`Database` — Singleton, который хранит настройки и открывает/закрывает JDBC-соединение на одну операцию. `ClientRepDb` содержит SQL, задаёт параметры `PreparedStatement` и преобразует строки в клиентов. `ClientDbAdapter` переводит общий контракт в эти SQL-операции. `DatabaseQueryDecorator` добавляет фильтрацию и сортировку. ORM и SQLite не используются.

## ж. Формат результата SELECT

Драйвер JDBC возвращает `ResultSet`. Он обходится через `next()`, значения извлекаются через `getLong`, `getString`, `getObject`. `ClientRepDb` превращает строки в `Client`, `Optional<Client>` или `List<ClientShort>`, а `COUNT(*)` — в `long`. `Database.withConnection` возвращает тип `T`, созданный переданной операцией. Незакрытый `ResultSet` наружу не передаётся.

## з. Одиночка

Singleton нужен, когда сервис должен иметь один экземпляр и общую точку доступа. В работе это сервис конфигурации/создания соединений. Одиночка не означает одно общее JDBC-соединение для всех запросов: соединения открываются на операцию, чтобы не смешивать потоки и транзакции. Недостаток паттерна — глобальное состояние; поэтому вызов сосредоточен в небольшом классе.

## и. Реализация и проверка Singleton

```java
final class Service {
    private Service() {}
    private static class Holder {
        private static final Service INSTANCE = new Service();
    }
    static Service getInstance() { return Holder.INSTANCE; }
}
```

Инициализация `Holder` выполняется JVM один раз. В JUnit: `assertSame(Service.getInstance(), Service.getInstance())`. В проекте дополнительно проверено получение одного экземпляра из параллельных потоков и закрытие соединений при успехе/ошибке SQL.

## й. Поля и методы класса

Поля объекта хранят его состояние, методы задают допустимое поведение и защищают инварианты. У клиента паспорт определяет идентичность; валидирующий конструктор не допускает некорректные данные. У репозитория путь определяет файл, а `add` проверяет уникальность и назначает ID.

Статические методы относятся к классу и не требуют готового экземпляра. Два примера: фабрики `ClientFileCodec.json()/yaml()` для создания настроенного кодека и `Database.getInstance()` для доступа к Singleton. Статическая функция проверки телефона также уместна до создания клиента. В UML статические члены подчёркиваются.

# Обязательная часть ЛР2

**7 классов и 1 интерфейс.** Пункты со звёздочками не входят в работу.

| Пункт | Где реализован |
|---|---|
| 1 | `ClientRepJson`: чтение/запись, поиск по ID, краткие страницы, сортировка по фамилии, добавление с новым ID, замена, удаление, количество |
| 2 | `ClientRepYaml`: те же операции с YAML через делегацию общей файловой логике |
| 3 | `ClientRepository`: общий интерфейс репозиториев; по уточнению используется реализация интерфейса и делегация вместо наследования конкретных классов |
| 4 | `ClientRepDb`: все SQL-операции через JDBC и PostgreSQL, без ORM и SQLite |
| 5 | `Database`: отдельный Singleton; `ClientRepDb` делегирует ему открытие JDBC-соединений |
| 6 | `ClientDbAdapter`: объектный Adapter, подключающий SQL-репозиторий к общему интерфейсу |
| 9 | Checkstyle подключён к `mvn verify`, код отформатирован |

Диаграмма: `class-diagram.svg`; редактируемый исходник: `class-diagram.puml`.

Проверка сборки и линтера: `mvn verify` из папки `лаб2`. Пример JSON: `mvn exec:java`.

`getKNShortList(k, n)` — страница с номером `k` из `n` кратких объектов, начиная с 1. Например, `(2, 20)` — записи 21–40. Файловые изменения сохраняются через `writeAll()`, чтение повторяется через `readAll()`. Отсутствующий ID даёт `Optional.empty()`, замена и удаление — `false`.

Для PostgreSQL создайте БД `hotel_lab2`. Подключение задаётся переменными `LAB2_DB_URL`, `LAB2_DB_USER`, `LAB2_DB_PASSWORD`; значения по умолчанию — `jdbc:postgresql://localhost:5432/hotel_lab2`, `postgres`, пустой пароль. `new ClientRepDb().initializeSchema()` создаёт учебную таблицу клиентов.

Singleton — сервис подключения, а не одно общее соединение: каждый SQL-метод закрывает своё соединение через try-with-resources. Клиенты сравниваются по паспорту; ID используется для операций репозитория.
